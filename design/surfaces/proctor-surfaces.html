Let Proctor hold your keyboard and mouse?

While Proctor posts a step, an event tap swallows your own input so your typing cannot land in the app it is driving.

This is the same mechanism a keylogger uses, on the Accessibility grant Proctor already holds. Two things stay true whatever happens: Stop always works, and the block never survives the process — quitting Proctor releases your input immediately.

The takeover notice is on, so the Mac will visibly say what is happening while your input is held.

Cancel leads, the confirming action trails, and the verb on the button is what will happen — not “OK”.

The notice that would explain this is switched off

You are turning on Hold the keyboard and mouse while Takeover notice is off.

Your keyboard and mouse will be held while Proctor acts, and nothing on screen will say why. The Mac will simply stop responding.

The recovery is the prominent action; the risky path stays available and unfilled. Every capability is paired with the drawing switch that announces it, and a mismatched pair is warned about rather than silently allowed.

Name browser-use to the model?

For pages Obscura cannot open — a browser’s own settings, an extension page, DevTools — Proctor can name the browser-use CLI instead.

browser-use is an autonomous agent. Its default local mode drives a real browser with your real logins, and nothing it does reaches Proctor’s audit trail.

Proctor will ship no command for it, only prose about which mode to run it in. It is never used as a fallback, and never pointed at your saved passwords, extensions or history.

Installing a CLI is consent to have a file. It is not consent for a process holding Accessibility to name that file to a model with a shell — which is why this is a separate, explicit decision.

Proctor wants to unlock this Mac

A short turn opens, macOS evaluates the unlock right, and Proctor relocks when the turn ends or you touch the machine.

The login window stays available, so you are never locked out.

Every unlock is its own turn with its own expiry. Nothing holds the door open across a session, so a crashed client cannot leave it open.

Read-only verbs never queue. The three marked DESTR carry the same destructive annotation the MCP tool carries, so a wrapper script can gate on it without parsing English.

ActionBlast radiusGate
Stop a runThe current run only. Nothing already done is undone. None. It is the kill switch — it must never be harder to reach than the thing it stops. Present on the HUD, the menu bar, the overlay and the TUI, all writing one latch.
Pause a runNothing. Reversible by definition. None, and a 15-minute cap so a forgotten pause cannot park the machine.
Drop a waiting runOne queued run, which comes back saying a person dropped it. None, but the refusal it produces is distinguishable from a timeout, because one is safe to retry and the other is a reason to ask first.
Hold the keyboard and mouseEvery keystroke on the Mac, for as long as a step is in flight. Named-consequence sheet, second press, and the disclosure above the button. Two invariants hold regardless: Stop works, and the block dies with the process.
Name browser-use to a modelAn autonomous agent, in a real browser, with real logins, outside the audit trail. Named-consequence sheet plus a launchd environment variable. Two independent gates, and no command template is ever shipped.
Unlock the screenThe lock screen, for a bounded turn. Alert with an explicit duration, a self-expiring turn, and the login window kept available so nobody is locked out.
proctor killA named process, or several by substring match. Prints what matched and waits for confirmation before --force. The policy gate applies first.
Quit ProctorThe window and the background agent. Any run in flight ends. Destructive styling, and copy that says both come back at the next login — so it reads as “off now”, not “uninstall”.
proctor guest stopA whole virtual machine and everything running in it. Names the guest and its provider, and refuses when the handle is ambiguous across two providers.
Stop is deliberately the one destructive action with no gate at all. Everything else here gets friction proportional to its blast radius, but a kill switch that asks a question is a kill switch that fails at the moment it is needed. It is reachable from four surfaces, and all four write the same latch.

1 · First run (3 steps)

1Intro — what Proctor is
exit: Skip setup → menu bar, no grants
2Permissions — the real macOS dialogs
exit: Back; auto-advance once both land
3Connect — copy the snippet
exit: Done → window demotes to the menu bar

2 · A supervised run (6 steps)

1A model calls a tool; the queue grants a lane
2Foreground demand computed and disclosed before anything runs
3Takeover notice and drawn pointer, if the batch will post
4Steps execute; each result names its plane and route
5A person touches the Mac → yield → paused
exits: Resume, Stop, or the 15-minute cap
6Finished — sealed, signed, and in the history

3 · Granting a capability (4 steps)

1Switch pressed in the Status window
2Sheet naming the consequence, not the mechanism
3Pairing check — is the notice that explains this switched off?
exit: turn the notice back on (prominent)
4Second press applies it at the next agent start
turning it off later never asks

4 · Supervising over SSH (3 steps)

1ssh mac-mini → proctor tui
2Five panes over one socket; updates pushed, never polled
3Stop writes the same latch the HUD does
open: whether the TUI may attach over the HTTP transport, which puts Stop behind a bearer token

5 · Checking a build in CI (3 steps)

1proctor doctor --json --lane mac gates the job
2proctor flow replay then proctor assert
3Exit code is the verdict: 1 is a failed check, 3 is nothing measured
the two must not be confused, which is why they are separate codes
