== TWO API FACTS THE FIXTURE FOUND BY GETTING THEM WRONG ==

1. VisionCapture.toNative DIVIDES.
   It takes a coordinate the model returned in the NORMALISED image it was
   handed and maps it back to native pixels. A first draft asserted it
   multiplied and read n.w = 10 against an expected 90 at scale 3. Getting
   this backwards puts every assertion at scale-times the right place on a
   Retina display, which is every display on this Mac.

2. RecognizedTextItem.boundingBox is CROP PIXELS; pointBox is points.
   Wire.swift:511-512 says so. A first draft asserted scale invariance on
   boundingBox and read 22 against 376 across 1x and 2x — the field working
   exactly as documented, and the test reaching for the wrong one. That is
   the mistake a caller makes, so the test now pins BOTH: boundingBox must
   grow with the density, and pointBox must not.
