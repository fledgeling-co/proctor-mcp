== PRO-0127, THE GAP ==
GuestHealth existed as a TYPE with nothing behind it. GuestHealthProbe is the
probe, and the distinction it exists for is measured rather than invented:
CASE-0029 established that SIGSTOP leaves a listener bound, so connect()
succeeds and the reply never comes. A probe that asks only 'did the socket
accept me' calls that guest healthy and a runner waits on it until its own
deadline fires.

  unreachable   nothing listening — start the guest
  stalled       accepted and silent — restart the AGENT inside it
  degraded      every beat in a run over 750ms, or a host-side failure that
                says nothing about the guest
  healthy       answered

Two rules that keep it honest. A run of beats decides latency, not one sample:
one slow beat on a machine running five simulators is noise. And an attempt
that could not be MADE is degraded, never unreachable — reporting a host-side
failure as the guest's has an operator restart a guest that was fine.

The report does not probe. proctor_doctor is called before anything is
established, and a health block that pinged would add to the load somebody is
running it to diagnose. Beats are recorded as a side effect of traffic the
session was making anyway, bounded to 5, and an attachment with no beat yet
reports unreachable with beatsSeen 0 rather than healthy.
