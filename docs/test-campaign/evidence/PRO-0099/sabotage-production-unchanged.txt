PRO-0099 — production path resolution proved unchanged by forcing the else branch
=================================================================================

THE METHOD, AND WHY IT IS NOT A DIFF. Reading the diff proves the literal was
moved into an `operator…` accessor. It does not prove that production still
REACHES that accessor. DEF-164's verifier established the standard used here:
disable the predicate at source so the else branch — the production branch — is
the one that executes inside a test process, then read the resolved path back and
compare it character for character with the literal the pre-change code resolved.

THE SABOTAGE. The three interlocks added by this item, each rewritten in place:

  Sources/ProctorCore/SwitchStore.swift:126
    guard TestProcess.isActive else { return operatorURL }
    → guard false else { return operatorURL }

  Sources/ProctorAgent/Session/SessionMaestro.swift:443
    guard AuditLog.isTestProcess else { return operatorMaestroDirectory }
    → guard false else { return operatorMaestroDirectory }

  Sources/ProctorAgent/Session/SessionIOSProcess.swift:231
    guard AuditLog.isTestProcess else { return operatorDeviceFrameDirectory }
    → guard false else { return operatorDeviceFrameDirectory }

The probe (Tests/ProctorAgentTests/PRO0099SabotageProbe.swift) was temporary and
was deleted after this run; the three sources were restored from a byte copy
taken before the edit and re-checked with `grep -rn "guard false else" Sources/`,
which reports nothing.

THE ASSERTION THAT MAKES THE REST MEAN ANYTHING is the first line of output.
`TestProcess.isActive` is TRUE — the process really is a test runner — and the
paths below still resolve to the operator's own. That rules out the reading where
the sabotage appeared to work only because the predicate happened to be false.
