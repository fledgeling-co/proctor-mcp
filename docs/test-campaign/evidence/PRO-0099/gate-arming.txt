PRO-0099 — operator_path_gate.py, armed in both directions
==========================================================

The gate's healthy state is silence, which is the state a check that cannot fire
is also in. So both of its modes are armed on fixture trees in
`scripts/campaign/test_instruments.py`, which runs inside the suite through
`Tests/ProctorCoreTests/CampaignInstrumentTests.swift` — so a dead check here is
a red suite rather than a quiet one.

ARMING FOUND TWO REAL BUGS, both bare-name collisions in PolicyStore.swift, and
both FALSE REDS — the direction that gets argued away rather than fixed:

  DEF-170  `enclosing_type` took the nearest type indented less than the site
           without asking whether that type still CONTAINED it. `final class
           Seams` closes 19 lines above the operator literal in
           `AuditLog.directory`, so the census attributed that literal to
           `Seams.directory`, matched no manifest entry, and reported a classed
           writer as an unclassed one.
           Fixed by measuring containment with a brace scan (`scope_end`).

  DEF-171  `declaration_body` resolved a dotted name to the FIRST declaration of
           that name inside the owning type rather than to the owner's own
           member. `Seams.directory` — a lock-guarded stored property one level
           in — comes first, and its body holds no test-process predicate, so the
           gate reported the audit trail's own interlock as a writer with no
           branch.
           Fixed by taking the SHALLOWEST declaration in range: a type's own
           member is the shallowest occurrence inside it, and anything deeper
           belongs to a nested type.

Both are recorded as fixtures in test_instruments.py so they cannot come back.

THREE SHAPES THAT CLEARED BOTH MODES — PRO-0099 gap-fix, 2026-08-22
================================================================================

REQ-085 said a new un-classed or un-seamed operator path fails the gate. The
verifier built three fixtures that did not, and all three are the same failure:
the gate resolving a site correctly and then throwing the resolution away.

  1  BARE-NAME COLLISION IN THE CENSUS. `run_census` accepted a site when either
     spelling matched an entry, with no test that the bare one was unambiguous.
     A `Legacy.operatorURL` added beside a `SwitchStore.operatorURL` the manifest
     classes bare gave `census=[] seams=[]`.
  2  THE LEAK CHECK SKIPPED A WHOLE FILE. `if declaration_body(other_lines, bare):
     continue` excused every reference in any file declaring that name — so a
     `Bypass.swift` with a member called `operatorURL` could call
     `SwitchStore.operatorURL` around its seam and pass. Without the colliding
     declaration the same call was caught, which is what made it look armed.
  3  A COMPOSED PATH PRODUCED NO CENSUS SITE AT ALL, and this is the sharpest,
     because it is exactly how the real `SwitchStore.operatorURL` is written:
     `url(home: FileManager.default.homeDirectoryForCurrentUser)` names no root
     literal, so the literal sweep never sees it. A new un-seamed twin needed no
     manifest entry.

WHAT CHANGED IN THE GATE

  A bare entry now carries a site only where that bare name has ONE qualified
  spelling in its file (`qualified_declarations`). Where two declarations answer
  to it, both sites are refused until the manifest says which is which.

  The leak rule reads two ways round. A qualified reach — `SwitchStore.operatorURL`
  — is refused from any other file, always. A bare reach is excused only in a file
  that declares that name itself, which is why the excuse exists:
  `PolicyStore.operatorDirectory` and `FlowStore.operatorDirectory` are different
  paths spelled alike.

  The census gained a second sweep, `composed_sites`. A `parameterised` entry is
  classed safe BECAUSE the root arrives as an argument, so the caller handing it
  one of `home_expressions` is the operator path — and that caller names no
  literal. `SwitchStore.url(home:)` was itself unclassed, which is what made its
  callers invisible; it now carries an entry, and `SwitchStore.operatorURL` has a
  census site for the first time.

AND THE AMBIGUITY RULE FOUND ONE ON ITS FIRST RUN. `Wire.swift` was classed on a
bare `socketPath`, and `DoctorReport` declares a field of the same name 1,286
lines further down. The gate went red on the real tree until the entry was spelled
`Wire.socketPath`:
